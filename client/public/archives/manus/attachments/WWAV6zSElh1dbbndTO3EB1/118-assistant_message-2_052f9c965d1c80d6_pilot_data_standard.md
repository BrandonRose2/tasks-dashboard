# PropertyMax Pilot Data and Task Standard

The expanded pilot may use only verified, non-sensitive operational data. Property records should include the **property code and name, Region 3 designation, property manager name, approved business email or phone reference when present, regional ownership reference, source-data note, and any known routing ambiguity**. Unit counts, vacancy rates, or operational metrics should be included only when they exist in the supplied PropertyMax source records; unavailable values must remain blank rather than being estimated.

Each ClickUp task should follow the structure below so communication remains actionable and consistent.

| Task section | Required content |
|---|---|
| Property context | Property code, property name, Region 3, and relevant manager/contact routing |
| Source context | What the existing PropertyMax record currently says, including any missing or conflicting field |
| Objective | A specific outcome that can be completed and verified |
| Action steps | Two to four practical steps using the source system and ClickUp |
| Acceptance criteria | Observable conditions for completing the task |
| Communication handoff | Which existing channel to use, what to post, and a reminder to link the task |
| Data boundary | Explicit instruction not to copy resident names, unit ledgers, financial data, credentials, or other sensitive details into ClickUp |

Task names should begin with an action verb and identify the property or Region 3 scope. Priorities should reflect operational urgency rather than executive visibility. Tasks remain unassigned unless a current ClickUp member is positively resolved.
